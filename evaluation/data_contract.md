# Evaluation data contract

The database is a persistence target for future gateway components. Values below are integration points; all measurements except the request query remain optional in `RequestLog` until their owning component supplies them.

Example request data:

```json
{
  "query": "...",
  "complexity": "medium",
  "selected_model": "cheap-model",
  "input_tokens": 1200,
  "output_tokens": 400,
  "latency_ms": 850,
  "estimated_cost": 0.002,
  "cache_hit": false
}
```

## Component outputs and persistence mapping

| Component | Future output | `RequestLog` field |
|---|---|---|
| Request/API | Query text | `query` |
| Complexity Agent | `simple`, `medium`, or `complex` | `complexity` |
| Context Optimization | `original_tokens`, `selected_tokens` | `context_before_tokens`, `context_after_tokens` |
| Model Router | Initial inference tier | `selected_model` |
| Generation/provider | Tier that actually generated the final response | `final_model` |
| Escalation retry | Preserve initial inference tier and record the final response tier | `selected_model`, `final_model` |
| Usage/cost measurement | Input/output/total token counts; estimated cost; latency in milliseconds | `input_tokens`, `output_tokens`, `total_tokens`, `estimated_cost`, `latency_ms` |
| Cache | Cache hit boolean, optional key and lookup duration | `cache_hit`, `cache_key`, `cache_lookup_latency_ms` |
| Quality Agent | `quality_score`, `quality_status` | `quality_score`, `quality_status` |
| Escalation | `escalated` boolean | `escalated` |
| Chat outcome | Whether a usable response was returned | `completed` |
| Fallback | `fallback_used` boolean | `fallback_used` |
| Context metric calculation | Reduction percentage, when available | `context_reduction_percent` |
| Database | Creation time | `timestamp` (generated by default) |

The log row has an automatically generated `id`. `total_tokens` is derived from input and output counts when both are known and the caller did not supply it. Context reduction is `((before - after) / before) * 100`; a zero `before` value produces `0`. Explicit derived values are preserved. Do not invent unavailable values: keep them null.

All fields other than `query` are optional. Validation requires non-negative token counts, latency, and supplied cost; quality score must be between 0 and 1. `estimated_cost` can be supplied directly, or estimated using configurable demo placeholder rates in `backend/app/services/cost_service.py`. These rates are not real provider prices; unknown models yield no estimate. See `metrics_api.md` for endpoints and aggregation definitions.

`selected_model` preserves its established meaning: the model tier routed before the initial inference attempt. It is not the provider/model fallback that may successfully generate that attempt. `final_model` is the actual tier producing the final response, after any fallback or quality escalation. Escalation retries must not overwrite `selected_model`. `escalated` denotes quality-based escalation and `fallback_used` denotes provider/model fallback; they are independent outcomes. Do not infer unknown historical values or backfill legacy model/completion/quality fields.

Trace events are stored separately in `request_trace_events` and linked to the request ID. Use `app.services.trace_service.record_event` to record `stage`, `event`, and JSON-compatible metadata; integrations should not access ORM models directly. `completed=true` rows alone form the completed eligible request population; `false` rows and legacy `null` rows are excluded. Escalation rate is completed escalated rows divided by all completed eligible rows. The success rate among evaluated escalations is final `pass` evaluations divided by completed escalated rows with final status `pass` or `fail`; the denominator is `escalation_success_eligible_attempts`. Missing, pending, and `indeterminate` statuses are excluded. `pass` is success, `fail` is unsuccessful, and either rate is `0.0` for an empty denominator.
